# v0.2.0 evaluation results

Run on 2026-10-16 at `15254a9` with the protocol and gates in [`evals/README.md`](../README.md), for the Claude Code writer only. The raw run (`evals/runs/v0.2.0`) is git-ignored; this file is the record.

**Verdict: SHIP for Claude Code.** Every gate passed. The Codex writer was not rerun; see Disclosures.

- Judges preferred the skill over the short rule in 44 of 48 groups and the rule in 2, on all 8 cases. The mean per-case preference was +0.88, 95% CI +0.73 to +0.98. In v0.1.0-rc2 it was 30 groups to 9, on 6 of 7 cases, +0.50.
- Under the skill, outputs averaged 318 words, against 499 under the short rule and 375 for the skill in v0.1.0-rc2.

## Length caps

Each cap is 1.5 times the case's reference solution, relative to the input, and was fixed before any run of the changed skill. C stayed within its cap in 11 of 24 generations and B in 1. C was over its cap in every trial on four cases:

| Case | C, mean ratio to input | Cap |
|---|---|---|
| PR description | 1.13 | 1.0 |
| Commit message | 0.61 | 0.5 |
| Runbook | 1.89 | 1.6 |
| Review comments | 0.71 | 0.6 |

The RFC was over in 1 of 3 trials. These four cases are where a further brevity change would show.

## Triggering

Recall was 83% on should-trigger queries and the false-positive rate 0% on near misses, over 60 runs. The misses are the same queries as in v0.1.0: q7, the support-team explainer (0 of 3), and q10, the handoff doc for a named colleague (1 of 3). The description did not change.

## Judge spot-check

The repository owner decided the five groups in the blind packet from `run.py calibrate` (Claude writer, one random trial per case) before seeing the key.

| Case, trial | Owner's call | Claude judge | Codex judge |
|---|---|---|---|
| ADR, t3 | skill | tie | skill (agree) |
| Runbook, t2 | skill | skill (agree) | skill (agree) |
| README, t3 | short rule | short rule (agree) | tie |
| Commit message, t3 | skill | skill (agree) | skill (agree) |
| RFC, t1 | skill | skill (agree) | skill (agree) |

Agreement: 4 of 5 with each judge, 8 of 10 verdicts overall, against 9 of 10 in v0.1.0. Both disagreements were ties where the owner had a preference, each a 2-to-2 split of the dimensions: the Claude judge on the ADR, and the Codex judge on the README. No judge preferred the response the owner ranked worse. The owner preferred the skill in four groups and the short rule in the README group, the case where the skill's net preference was lowest (+3). Five groups are enough to rule out a badly miscalibrated judge, not to measure small biases, and they cover the Claude writer only.

## Disclosures

- **Codex writer not rerun.** At the owner's choice, to stay within the Codex plan's usage limits, this run measured the Claude Code writer only. Codex still judged every group. v0.1.0 found that the short rule did as well as the skill with Codex, and that recommendation is not re-measured here.
- **Recovered release.** The release pull request (#3) was merged before this file existed, so the release workflow tagged nothing. This file was committed afterwards and v0.2.0 tagged by hand, as README.md, "Versioning", describes.
- **One revision after a smoke run.** The skill change in #2 was revised once after a one-trial smoke run: the note to the user got a word budget, and "how it was found" got the examples "reproduction steps, log searches, and dead ends". The review-comments fixture contains all three, so that case carries a fitting risk.
- **Unpinned judge model.** The Codex judge used the CLI's default model, which the runner does not record.
